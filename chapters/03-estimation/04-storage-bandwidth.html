Estimating storage and bandwidth

Storage answers two design questions: does the data fit on one machine (if not, it must be partitioned) and which kind of store fits its size and shape (rows in a database, blobs in object storage). The basic formula is short; the overheads are where people slip.

Worked example: posts and photos

text
Assumptions
  200M new posts/day, ~1 KB each (rounded up, see lesson 1)
  10% of posts carry one photo; the client uploads a ~2 MB original,
  and we keep only resized versions totaling ~500 KB
  retention: 5 years; database replication factor 3

Post rows
  200M x 1 KB          = 2 x 10^8 x 10^3 B = 2 x 10^11 B = 200 GB/day
  x 365                = 73 TB/year
  x 5 years            = 365 TB
  x 3 replicas         = ~1.1 PB of database storage

Photos
  20M x 500 KB         = 2 x 10^7 x 5 x 10^5 B = 10^13 B = 10 TB/day
  x 365                = 3.65 PB/year
  x 5 years            = ~18 PB in object storage

Two conclusions fall straight out. First, media is about 50x larger than the rows that describe it, so photos belong in object storage such as Amazon S3 and only their metadata in a database. Second, 365 TB of post rows (1.1 PB with replicas) is far beyond one database server, so the post table must be sharded (Chapter 7).

Bandwidth

Ingress (data coming in) is write rate × request size. Egress (data going out) is read rate × response size. Egress is usually much larger and costs money, often a few cents per GB in public clouds. Network speeds are quoted in bits per second, so divide by 8 to get bytes.

text
Ingress: photo uploads
  20M photos/day x 2 MB original   = 40 TB/day
  40 x 10^12 B / 86,400 s          = ~460 MB/s = ~3.7 Gbit/s average
  x peak factor 3                  = ~11 Gbit/s

Egress: photo views
  100M DAU x 50 photo views/day    = 5B views/day
  5 x 10^9 / 10^5 s                = 50,000 views/s average, 150,000/s peak
  50,000 x 200 KB per view         = 10^10 B/s = 10 GB/s = 80 Gbit/s average
  at peak                          = ~240 Gbit/s
  origin traffic if the CDN serves 95% of bytes = 5% of 240 = ~12 Gbit/s

240 Gbit/s is the output of dozens of servers' network cards and needs presence near users worldwide, so a CDN isn't optional here. With a 95% CDN hit ratio, the origin only serves about 12 Gbit/s at peak.

Pitfall
Bits versus bytes
Disks and files are sized in bytes (B); network links in bits (b). 1 Gbps is 125 MB/s, not 1 GB/s. Mixing them up is an 8x error, the most common mistake in bandwidth estimates. Write the unit on every line.
Tip
Price the egress
10 GB/s average egress is 864 TB/day, about 26 PB per month. At an illustrative $0.02 per GB that is about $520,000 a month, often more than the servers. Mentioning cost when bandwidth is large is a strong senior signal, and it motivates CDNs, better compression and smaller image formats.
In the interview
Leave a table on the board
Write the results as a compact table: average and peak QPS for reads and writes, storage per day, per year and over 5 years, and peak ingress and egress. You will point back to it repeatedly when justifying shards, caches and CDNs.
