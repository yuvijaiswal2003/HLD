Forward proxies, reverse proxies, Nginx and Envoy

A proxy is an intermediary that receives a request and makes it on someone else's behalf. The key question is: on whose behalf?

A forward proxy acts for clients. Clients are configured to send their traffic through it, and the destination server sees the proxy's IP rather than the client's. Companies use forward proxies to filter and log employees' outbound traffic, to cache downloads, or to give all outbound calls one fixed IP that partners can allowlist. A reverse proxy acts for servers. Clients think they are talking to the website; the reverse proxy receives the request and forwards it to one of the backend servers, which clients never see directly.

What a reverse proxy does

FunctionWhat it means
Load balancingSpreads requests across healthy backends (Chapter 4)
TLS terminationDecrypts HTTPS once at the edge, so backends handle plain HTTP or re-encrypted internal traffic
RoutingSends /api/* to one service and /static/* to another, by path, host or header
Caching and compressionServes repeated responses from memory or disk; gzip or brotli compression
ProtectionRate limiting, request size limits, IP blocking; hides backend topology
Buffering slow clientsReads a slow mobile upload fully before passing it on, so app workers aren't tied up
ObservabilityAccess logs and metrics for every request in one place
text
upstream api_backend {
    least_conn;
    server 10.0.1.11:8080;
    server 10.0.1.12:8080;
    keepalive 64;                  # reuse upstream connections
}
server {
    listen 443 ssl http2;
    server_name api.example.com;
    location /api/ {
        proxy_pass http://api_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

The Nginx config above terminates TLS on port 443, sends /api/ traffic to two backends using least-connections balancing, and keeps a pool of idle upstream connections. Because backends see the proxy's IP, the proxy passes the original client IP in the X-Forwarded-For header.

Nginx

Strengths
  • Very fast event-driven web server and reverse proxy
  • Excellent at static files, TLS termination and caching
  • Huge ecosystem; simple config files
Weaknesses
  • Open-source version reloads config from files rather than through a dynamic API
  • Fewer built-in service-mesh features
Use whenEdge reverse proxy, static file server, simple load balancing and caching.

Envoy

Strengths
  • Built at Lyft for microservices; configured dynamically via its xDS APIs
  • First-class HTTP/2 and gRPC, retries, circuit breaking, rich metrics and tracing
  • The data plane behind Istio and many API gateways
Weaknesses
  • More complex to configure by hand
  • Usually needs a control plane to manage it
Use whenSidecar proxy in a service mesh, gRPC-heavy internal traffic, dynamic API gateways.

HAProxy is another widely used high-performance load balancer and proxy. Load balancers, API gateways and service-mesh sidecars are all specialized reverse proxies; Chapters 4 and 11 cover them.

In the interview
Name what the proxy does for you
Don't just draw an “Nginx” box. Say: “A reverse proxy tier terminates TLS, routes /api to the API service and /ws to the WebSocket gateways, enforces per-IP rate limits, and keeps keep-alive pools to the backends.” Each function is a decision the interviewer can see.
