Remember for the interview

  1. 01Snowflake IDs pack 1 sign bit, a 41-bit millisecond timestamp (about 69 years from a custom epoch), a 10-bit machine ID (1,024 workers) and a 12-bit sequence (4,096 IDs per ms per worker) into 64 bits. They stay unique only if worker IDs are unique and clocks never run backwards.
  2. 02Time-ordered keys (Snowflake, UUID v7, ULID) keep B-tree inserts at the right-hand edge of the index; random UUID v4 keys scatter inserts across it. On range-partitioned stores such as Bigtable and Spanner the rule flips: sequential keys create a hot tablet.
  3. 03A Bloom filter never gives false negatives. Size it with m = −n·ln p / (ln 2)² and k = (m/n)·ln 2: about 9.6 bits and 7 hashes per item for 1%, no matter how large the items are.
  4. 04A Count-Min Sketch estimates frequencies in fixed memory and only overestimates, by at most εN with probability 1 − δ. Use it to find heavy hitters, not to report exact long-tail counts.
  5. 05HyperLogLog counts distinct items in 12 KB in Redis with about 0.81% standard error. Merge sketches with PFMERGE to get unions, and never add daily unique counts together.
  6. 06Merkle trees find the ranges where replicas differ in O(log n) hash comparisons. Gossip spreads membership in O(log N) rounds. Failure detectors such as SWIM and phi accrual can only suspect a node, so pair them with fencing.
  7. 07For nearby search, a geohash prefix is a cell (6 characters is about 1.2 × 0.6 km, 5 is about 4.9 km). Always query the 8 neighbouring cells and re-rank by true distance. Quadtrees adapt to density, S2 handles precise region coverings, and H3 hexagons suit area aggregation.
  8. 08OT transforms position-based edits through a central server, which is how Google Docs works. CRDTs converge without coordination but carry extra metadata and tombstones; they suit offline-first and peer-to-peer apps.
  9. 09For distributed Top-K, partition events by key before counting, keep per-minute buckets for sliding windows and serve precomputed results from a cache. Merging local top-K lists computed from unpartitioned data gives wrong answers.
  10. 10Fan-out on write makes reads cheap but costs one write per follower; fan-out on read makes writes cheap but amplifies tail latency. Use a hybrid to handle celebrity accounts.
