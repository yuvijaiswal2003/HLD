Circuit breakers, bulkheads, load shedding and degradation

Retries handle blips lasting milliseconds to seconds. When a dependency is down for minutes, you need to stop calling it, protect your own resources, and keep serving whatever you still can. Four patterns do this: circuit breakers, bulkheads, load shedding and graceful degradation.

Circuit breaker

A circuit breaker wraps calls to a dependency and tracks failures. In CLOSED state calls flow normally. When the failure rate crosses a threshold (for example over 50% of at least 20 calls in a 10-second window) it trips to OPEN: calls fail immediately without touching the network, and the caller uses a fallback. After a cool-down it moves to HALF-OPEN and lets a few trial calls through. If they succeed, it closes; if any fail, it opens again. Failing fast frees threads, gives the dependency room to recover, and turns a 5-second timeout into a 1-millisecond error.

python
import time

class CircuitOpen(Exception):
    pass

class CircuitBreaker:
    """Minimal breaker: opens after N consecutive failures.
    Production breakers use a failure rate over a rolling window
    and limit how many trial calls run in HALF_OPEN."""
    def __init__(self, threshold=5, cooldown=30.0):
        self.threshold, self.cooldown = threshold, cooldown
        self.failures, self.state, self.opened_at = 0, "CLOSED", 0.0

    def call(self, op):
        if self.state == "OPEN":
            if time.monotonic() - self.opened_at < self.cooldown:
                raise CircuitOpen()          # fail fast; caller uses a fallback
            self.state = "HALF_OPEN"         # cool-down over: let a trial through
        try:
            result = op()
        except Exception:
            self.failures += 1
            if self.state == "HALF_OPEN" or self.failures >= self.threshold:
                self.state, self.opened_at = "OPEN", time.monotonic()
            raise
        self.failures, self.state = 0, "CLOSED"
        return result
  • Require a minimum request volume before tripping, so 2 failures out of 3 calls at 3 a.m. do not open the circuit.
  • Count timeouts and 5xx as failures, not 4xx: a 404 means the dependency is healthy.
  • Keep breakers per dependency, ideally per host or endpoint, so one bad replica does not cut off the healthy ones.
  • Netflix Hystrix popularized the pattern (it is now in maintenance mode); today you use Resilience4j, Polly, or Envoy's outlier detection in a service mesh.

Bulkheads

Ships are divided into watertight compartments so one breach does not sink the ship. A bulkhead isolates resources the same way. Suppose a product page service uses one shared pool of 200 threads for all downstream calls, and the recommendation service starts hanging until its 30-second timeout. At 20 recommendation calls per second, Little's Law gives 20 × 30 = 600 calls in flight, far more than 200 threads. The pool fills up, and checkout, served by the same process, starts failing too. Give each dependency its own bounded pool and the hanging dependency can only exhaust its own slice.

Bulkheads scale up to whole architectures: separate clusters for premium and free tiers, or cell-based architecture, where the system is split into independent copies (cells) that each serve a slice of customers, so a bad deploy or poison request hurts one cell, not everyone.

Load shedding and backpressure

When demand exceeds capacity and you accept everything, queues grow until wait time exceeds the clients' timeouts. Servers then spend their capacity on requests nobody is waiting for: throughput looks high while goodput (useful completed work) collapses. Load shedding rejects excess work early and cheaply: cap concurrent requests or queue length, return a fast 503 or 429, shed low-priority traffic (analytics, prefetch) before critical traffic (checkout), and drop queued requests whose deadline has already passed. Backpressure is the cooperative version: bounded queues and flow control (TCP windows, HTTP/2 and gRPC flow control, pull-based Kafka consumers) tell producers to slow down instead of letting work pile up. Chapter 9 covers backpressure in queues.

Graceful degradation

  • Serve stale cached data when the source is down, flagged as possibly outdated.
  • Hide non-critical features: replace personalized recommendations with a precomputed bestseller list.
  • Switch to read-only mode when the write path is impaired.
  • Lower quality: smaller images, lower video bitrate, fewer search facets.
  • Accept writes into a durable queue and process them later, telling the user "processing".
  • Keep kill switches (feature flags) so operators can turn expensive features off in seconds.

In the interview
Tell the story as a chain
"A call to recommendations has a 200 ms timeout and one retry with jitter. If its failure rate passes 50%, the breaker opens and we fall back to the cached bestseller list. Its thread pool is capped at 20, so even if it hangs, checkout keeps working. If the whole service is overloaded we shed prefetch traffic first." Naming concrete numbers and fallbacks beats listing pattern names.
